* What this is

One flake for every machine I run: a storage server, two Kubernetes (k3s) clusters (see [[file:kubernetes/README.org][kubernetes/README.org]]), a development machine and the Mac. Nix is used as a configuration language only: no loops, conditions or custom functions in machine definitions.

Every machine is a row of four columns: its hardware, its OS, its roles and its users. Each column is a folder, one module per file; ~desktop-umbriel~ and ~hyperv-gpu-pv~ are kept but used by no machine.

| Folder                            | Holds                                                                                                             |
|-----------------------------------+-------------------------------------------------------------------------------------------------------------------|
| ~hardware/~                       | what a machine is: boards, boot, NICs, kernel modules; ~disko.nix~ holds the disk layouts (~diskoConfigurations~) |
| ~os/~                             | the operating system every machine runs: ~common~ (NixOS and the Mac), ~base~, ~ephemeral~, ~darwin~              |
| ~roles/~                          | what a machine does: ~workstation~, ~desktop-kde~, ~desktop-umbriel~, ~nas~, ~builder~                            |
| ~users/~                          | who uses it: accounts and home-manager configuration (~artur~, ~tatyana~, ~yoba~ on the Mac)                      |
| ~kubernetes/~                     | the ~kubernetes-node~ and ~storage-server~ roles, the cluster add-ons, and the platform Argo CD syncs             |
| ~flake.nix~                       | inputs, and one row per machine choosing from each folder; the clusters and their nodes                           |
| ~kubernetes/secrets/~             | agenix secrets; ~rekeyed/~ holds them encrypted per machine                                                       |

* How a machine is built

+ ~common~ (also on the Mac): the Nix daemon's settings and the time zone.
+ ~base~: ~common~, agenix, disko, the latest kernel, NetworkManager, avahi for ~.local~ names, resolved for unicast DNS, SSH. Addresses come only from DHCP reservations (by MAC) and SLAAC (EUI-64), so they stay the same across reinstalls.
+ ~ephemeral~: ~/~ is a tmpfs and ~/etc~ a read-only overlay; users exist only as declared. What survives a reboot is on ~/persist~:

| Module            | Persisted                                                                                                     |
|-------------------+---------------------------------------------------------------------------------------------------------------|
| every machine     | ~/var/lib/{nixos,systemd,NetworkManager}~, ~/var/log~, SSH host keys (the agenix identity), ~/etc/machine-id~ |
| kubernetes-node   | ~/var/lib/{rancher,kubelet,iscsi}~; ~/etc/rancher~, ~/etc/cni~ and ~/etc/iscsi/*~ link into them              |
| artur-workstation | artur's ~Documents~, ~Downloads~, ~.ssh~, ~.config/mozilla~, ~.local/share/direnv~, ~.local/state/bash~       |
| nas               | ~/var/lib/{samba,target,containers,private}~; homes and app state are ZFS datasets                            |

+ disko ~vm~ (~diskoConfigurations.vm~): the VMs' disk, an ESP and a btrfs with ~nix~ and ~persist~ subvolumes.
+ ~workstation~: home-manager, unfree packages and the font on the development machine and the Mac; on the Mac also Homebrew's apps and the Dock.
+ ~builder~: storage-station builds at idle priority; the Mac builds aarch64-linux in nix-darwin's ~linux-builder~ VM and sends x86_64-linux builds to storage-station.
+ ~artur~: the account on every NixOS machine; ~artur-workstation~ adds the persisted home, the desktop groups, the registry token and the Linux-only home configuration (Emacs on Wayland, Firefox, Alacritty). ~homeModules.artur~ is the home configuration on the development machine and, as ~yoba~, on the Mac, where bash from Nix is the login shell and the Mac keeps its own CLI tools.

* Common actions

Run from a checkout on a development machine (or on storage-station, for storage-station), inside ~nix develop~.

Rebuild the Mac (the first time, before ~darwin-rebuild~ exists: ~sudo nix run nix-darwin -- switch --flake .#yoba-book-pro~):
#+begin_src bash
sudo darwin-rebuild switch --flake .#yoba-book-pro
#+end_src

The Mac builds aarch64-linux in nix-darwin's ~linux-builder~ VM and x86_64-linux on storage-station, so it deploys every machine as the development machine does.

Deploy a server or cluster node:
#+begin_src bash
deploy .#storage-station
#+end_src

Rebuild a development machine, or storage-station on the box itself:
#+begin_src bash
nixos-rebuild switch --flake .#nixos-development-environment --use-remote-sudo
#+end_src

Install a VM: boot it into the NixOS installer over the network (the router serves netboot.xyz), then keep its identity across the install:
#+begin_src bash
mkdir -p keep/persist && ssh <machine>.local 'sudo tar -C / -c etc/machine-id etc/ssh' | tar -C keep/persist -x --wildcards 'etc/machine-id' 'etc/ssh/ssh_host_*'
nix run github:nix-community/nixos-anywhere -- --flake .#<machine> --target-host root@<host> --extra-files keep --chown /persist/etc root:root
#+end_src

Flash a Raspberry Pi: build its image on the Mac (its ~linux-builder~), write the machine's host keys and machine ID into its root, and ~dd~ it to the SD card; it grows to the card on first boot.
#+begin_src bash
nix build .#nixosConfigurations.k8s-node-aarch64-1.config.system.build.raspberryPiImage
#+end_src

Replace a k3s server: drain it, ~kubectl delete node <machine>~, install it as above; it joins the cluster's ~init~ server as a new etcd member.

Add or change a secret, then encrypt it for the machines that use it. Only the Mac can: the secrets are encrypted to its SSH key (~/Users/yoba/.ssh/id_ed25519~), the one master identity:
#+begin_src bash
agenix edit kubernetes/secrets/<name>.age
agenix rekey
#+end_src

Push the platform to Argo CD:
#+begin_src bash
nix run .#push-platform
#+end_src
