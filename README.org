* What this is

One flake for every machine I run: a storage server, two Kubernetes (k3s) clusters (see [[file:kubernetes/README.org][kubernetes/README.org]]), a development machine, a Raspberry Pi and the Mac. Nix is used as a configuration language only: the machine and cluster definitions in ~flake.nix~ have no loops, conditions or custom functions; ~kubernetes/default.nix~ generates the cluster nodes from them.

Every machine is a row of four columns: its hardware, its OS, its roles and its users. Each column is a folder; a file holds the modules that belong together.

| Folder                | Holds                                                                                                             |
|-----------------------+-------------------------------------------------------------------------------------------------------------------|
| ~hardware/~           | what a machine is: boards, boot, NICs, kernel modules; ~disko.nix~ holds the disk layouts (~diskoConfigurations~) |
| ~os/~                 | the operating system every machine runs: ~common~ (NixOS and the Mac), ~base~, ~ephemeral~, ~darwin~              |
| ~roles/~              | what a machine does: ~workstation~, ~desktop-kde~, ~nas~, ~builder~                                               |
| ~users/~              | who uses it: accounts and home-manager configuration (~artur~, ~tatyana~, ~yoba~ on the Mac)                      |
| ~kubernetes/~         | the ~kubernetes-node~ and ~storage-server~ roles, the cluster add-ons, and the platform Argo CD syncs             |
| ~flake.nix~           | inputs, and one row per machine choosing from each folder; the clusters and their nodes                           |
| ~kubernetes/secrets/~ | agenix secrets; ~rekeyed/~ holds them encrypted per machine                                                       |

* How a machine is built

+ ~common~ (also on the Mac): the Nix daemon's settings and the time zone.
+ ~base~: ~common~, agenix, disko, NixOS's default kernel, systemd-networkd, resolved for unicast DNS (machines reach each other as ~<hostname>.internal.burned.host~, which the router publishes; no mDNS), clatd, SSH. Wired interfaces take DHCPv4 (by MAC, for the reservations) and SLAAC (EUI-64), so addresses stay the same across reinstalls. Where the router offers IPv6-only (option 108), a machine drops IPv4 and clatd reaches IPv4 through the router's NAT64; so do the cluster nodes on VLAN 33, except storage-station's ~br0~, which keeps IPv4 for the home network.
+ ~ephemeral~: ~/~ is a tmpfs and ~/etc~ a read-only overlay; users exist only as declared. What survives a reboot is on ~/persist~:

| Module            | Persisted                                                                                                        |
|-------------------+------------------------------------------------------------------------------------------------------------------|
| every machine     | ~/var/lib/{nixos,systemd}~, ~/var/log~, SSH host keys (the agenix identity), ~/etc/machine-id~                   |
| kubernetes-node   | ~/var/lib/{rancher,kubelet,iscsi}~, ~/opt/cni/bin~; ~/etc/rancher~, ~/etc/cni~ and ~/etc/iscsi/*~ link into them |
| artur-workstation | artur's ~Documents~, ~Downloads~, ~.ssh~, ~.config/mozilla~, ~.local/share/direnv~, ~.local/state/bash~          |
| nas               | ~/var/lib/{samba,target}~; homes and app state are ZFS datasets                                                  |

+ ~nas~: Avahi, the only one on any machine, announces the SMB share and Time Machine to the Macs on ~br0~ and ~br33~. sanoid snapshots the datasets of both pools, each at its own minute of the hour, and thins them out (24 hourly, 14 daily, 3 monthly; media 7 daily). ~tank/kubernetes-postgres~, the Postgres volumes of the main cluster, has no sanoid entry and no snapshots; their backups are CloudNativePG's in RustFS. syncoid copies the RustFS volume of the main cluster, which holds the Postgres backups, from ~tank~ to ~dozer/backups/rustfs~ once a day; sanoid takes no snapshots of the copy and keeps seven dailies of it.
+ disko ~vm~ (~diskoConfigurations.vm~): the VMs' disk, an ESP and a btrfs with ~nix~ and ~persist~ subvolumes.
+ ~workstation~: home-manager, unfree packages and the font on the development machine and the Mac, and the newest kernel on the development machine; on the Mac also the Dock.
+ ~builder~: storage-station serves its store as the binary cache and builds only its own rebuilds, at idle priority; the Mac sends x86_64-linux builds to the development machine.
+ ~artur~: the account on every NixOS machine; ~artur-workstation~ adds the persisted home, the desktop groups, the registry token and the Linux-only home configuration (Emacs on Wayland, Firefox). ~homeModules.artur~ is the home configuration on the development machine and, as ~yoba~, on the Mac, where bash from Nix is the login shell and the Mac keeps its own CLI tools.

* Common actions

Run from a checkout on a development machine (or on storage-station, for storage-station), inside ~nix develop~.

Rebuild the Mac (the first time, before ~darwin-rebuild~ exists: ~sudo nix run nix-darwin -- switch --flake .#yoba-book-pro~):
#+begin_src bash
sudo darwin-rebuild switch --flake .#yoba-book-pro
#+end_src

The Mac builds x86_64-linux on the development machine, so it deploys every x86 machine as the development machine does. It has no aarch64-linux builder.

Deploy a server, a cluster node or a Raspberry Pi:
#+begin_src bash
deploy .#storage-station
#+end_src

Rebuild a development machine, or storage-station on the box itself:
#+begin_src bash
nixos-rebuild switch --flake .#nixos-development-environment --use-remote-sudo
#+end_src

Install a VM: boot it into the NixOS installer over the network (the router serves netboot.xyz), then keep its identity across the install:
#+begin_src bash
mkdir -p keep/persist && ssh <machine>.internal.burned.host 'sudo tar -C /persist -c etc/machine-id etc/ssh' | tar -C keep/persist -x --wildcards 'etc/machine-id' 'etc/ssh/ssh_host_*'
nix run github:nix-community/nixos-anywhere -- --flake .#<machine> --target-host root@<host> --extra-files keep --chown /persist/etc root:root
#+end_src

Flash a Raspberry Pi: build its image, write the machine's host keys and machine ID into its root, and ~dd~ it to the SD card; it grows to the card on first boot.
#+begin_src bash
nix build .#nixosConfigurations.k8s-node-aarch64-1.config.system.build.raspberryPiImage
#+end_src

Replace a k3s server: drain it, ~kubectl delete node <machine>~, install it as above; it joins the cluster's ~init~ server as a new etcd member.

Generate the secrets that have a generator (passwords, tokens) and are not there yet, then encrypt them for their machines; only the Mac can, as below:
#+begin_src bash
agenix generate
agenix rekey
#+end_src

Add or change a secret, then encrypt it for the machines that use it. Only the Mac can: the secrets are encrypted to its SSH key (~/Users/yoba/.ssh/id_ed25519~), the one master identity:
#+begin_src bash
agenix edit kubernetes/secrets/<name>.age
agenix rekey
#+end_src

Push the platform to Argo CD:
#+begin_src bash
nix run .#push-platform
#+end_src
